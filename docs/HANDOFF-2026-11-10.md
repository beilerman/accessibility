## How research is done

The helper scripts are in `scripts/research/`.

1. **Brief a research agent** with one slug per line, giving the slug, its site and the existing notes so nothing is duplicated (see the format below). Ask it to return JSON:
   - for depth notes: `[{slug, facts:[{domain, text, url, quote}]}]`
   - for new places: records that include `address_quote`.

   Each line of a brief looked like this:
   ```
   - slug taft-museum-of-art (Taft Museum of Art, site https://www.taftmuseum.org/). Already have: <existing note texts separated by " / ">
   ```
2. **Extract the result.** `python3 scripts/research/grab.py <agent-output.jsonl> out.json` pulls the agent's final JSON. Don't read the transcript directly.
3. **Verify the quotes.** `python3 scripts/research/verify.py out.json` re-fetches each URL, substring-matches the normalized quote, and writes `out.verified.json`.
   - Misses are usually whitespace or `&amp;` differences, so check them by hand.
   - Sites that block scripts are checked in Chrome with javascript_tool: the Symphony (form redirect) and AMC (Cloudflare). Newport Aquarium (Akamai) also needs Chrome.
4. **Write the notes yourself** in plain words from the verified quotes. Each note cites exactly one page; split any note that draws on two.
5. **Apply them:**
   - `python3 scripts/research/apply_depth.py spec.json [date]` appends notes. The spec format is `{slug: [[domain, text, url, source_type?, quote?]]}`.
   - `python3 scripts/research/add_places.py places.json [date]` adds new places. Each fact is `[domain, text, url, source_type, published_at, quote?]`.
   - Always pass the verified quote. It is stored in `pipeline/evidence/quotes.json` (never shown on the site) so the weekly monitor can tell whether a changed page still supports the note.
   - Then run `python3 pipeline/check_sources.py --new-only` and commit the new snapshot, or CI fails.
   - For rechecks: `python3 scripts/research/queue.py recheck 8` prints the brief, and `python3 scripts/research/recheck.py spec.json [date]` records the result (`{note_id: quote}`).
6. **Choose `source_type` carefully.** It is one of venue_official, operator_official, partner_official or public_agency. A unit test fails if a note marked venue_official cites a different domain from the place's website.
7. **When adding places,** also add their routes to `e2e/accessibility.spec.ts`, and update the category lists in `src/__tests__/venue-expansion.test.ts` (for example the Food & drink list).

**Rules:**
- Never infer; unknown stays unknown.
- Don't name venue staff, children or companions, or anyone's private medical details.
- AI images are cropped above ground and labeled, and never generated from copyrighted reference photos.
